# MeRGBW Controller: LT-06 и Stream Deck

Локальный контроллер на Go для **MeRGBW LT-06**. Один процесс `sunset` принимает HTTP-команды от Stream Deck, последовательно отправляет их по BLE и сохраняет соединение с лампой. Адрес по умолчанию — `127.0.0.1:18765`.

[English documentation](README.md)

## Совместимость и статус проверки

- Целевое устройство — LT-06: advertising service `3519`, GATT service `FFF0`, запись в `FFF3`.
- **Go BLE-путь проверен на одном LT-06 под macOS 2026-10-21:** ON/OFF, белый и RGB-цвета, яркость 0/50/100% и все шесть локальных пресетов с визуальным подтверждением пользователя. См. [отчёт аппаратной проверки](specs/002-ble-command-execution/hardware-verification.md). Ранее пакеты ON/OFF также проверялись через nRF Connect.
- Проверка относится к этому устройству и окружению. Совместимость других устройств из приложения MeRGBW не подтверждена.
- Встроенные [сцены](#сцены): **2026-10-25 на одной LT-06 каждый ID `80`–`93` дал эффект.** Названия сцен описывают то, что показала эта лампа. См. [отчёт проверки сцен](specs/009-full-command-scene-support/hardware-verification.md).
- Считывание реального состояния и музыка не реализованы. Программные переходы RGB/яркости и наблюдения пользователя для домашнего варианта описаны ниже.

## Готовые релизы

В [GitHub Releases](https://github.com/obalunenko/mergbw-controller/releases) доступны архивы `sunset_vX.Y.Z_darwin_arm64.tar.gz` (Apple Silicon), `darwin_amd64` (Intel Mac), `linux_amd64` и `linux_arm64`. В каждом находятся исполняемый файл, обе инструкции и лицензия. Скачайте `SHA256SUMS` и перед распаковкой сравните SHA-256 архива (`shasum -a 256 <archive>` на macOS, `sha256sum <archive>` на Linux) с соответствующей строкой.

Запустите из распакованной папки, заменив пример identity идентификатором своей лампы:

```sh
./sunset --identity AA:BB:CC:DD:EE:FF init
./sunset serve
```

Для самостоятельных архивов Go, Node и Task не нужны. На macOS отдельному CLI требуется разрешение Bluetooth для запускающего терминала; на Linux нужны BlueZ/D-Bus и адаптер. Установщик плагина Stream Deck 0.2 для macOS, `com.obalunenko.mergbw.development.streamDeckPlugin`, содержит собственный контроллер и использует настройку через панель, описанную ниже.

Отправка тега `vX.Y.Z` или `vX.Y.Z-prerelease` запускает [release workflow](.github/workflows/release.yml). Публикация ждёт успешного CI, всех четырёх нативных архивов контроллера и development-установщика плагина с обеими архитектурами. Проверяются извлечённые байты, права файлов и локальные ad-hoc-подписи; Developer ID и учётные данные нотариализации не нужны. Релиз содержит `SHA256SUMS`, сгруппированные заголовки и описания коммитов, авторов, ссылки на коммиты и полный changelog от ближайшего достижимого релизного тега. Первый релиз включает всю историю; коммиты без PR тоже учитываются. Предварительные теги публикуются как prerelease. Повторный запуск сохраняет опубликованный релиз; прерванную загрузку в черновик можно повторить.

Локальные проверки для сопровождающего проекта (для release notes нужны тег и полная история Git):

```sh
task release:test
task release:archive RELEASE_TAG=v1.0.0
task release:notes RELEASE_TAG=v1.0.0 RELEASE_REPOSITORY=obalunenko/mergbw-controller
```

Результаты записываются в `dist/`; локальные команды не публикуют релиз. Версии, сообщаемые контроллером и плагином, по-прежнему задаются в исходниках и манифесте независимо от релизного тега репозитория.

## 1. Сборка на macOS из исходников

Нужны **Go 1.27.0+** с [go.dev/dl](https://go.dev/dl/) и **Xcode Command Line Tools** с clang и macOS SDK. Если инструментов Apple нет, установите их и дождитесь завершения:

```bash
xcode-select --install
```

Используется обычный компилятор Go и библиотека `tinygo.org/x/bluetooth v0.16.0`. Компилятор TinyGo не требуется. Backend macOS использует CoreBluetooth через CGO, поэтому сборка выполняется на Mac — см. [официальные требования библиотеки](https://github.com/tinygo-org/bluetooth/blob/v0.16.0/README.md#macos).

```bash
git clone https://github.com/obalunenko/mergbw-controller.git
cd mergbw-controller
go tool -modfile=tools/task/go.mod task tools
task setup -- --identity AA:BB:CC:DD:EE:FF
task run
```

Замените пример identity значением из рекламы своей лампы, как описано ниже. `task setup` загружает модули приложения, собирает `sunset` и создаёт отсутствующие настройки. Существующие настройки сохраняются. Контроллер и закреплённые модули инструментов разработки требуют Go 1.27.0 или новее. Go и Xcode установите отдельно; системная служба не создаётся.

Отдельные шаги подготовки:

```bash
task deps
task build
task init -- --identity AA:BB:CC:DD:EE:FF
```

Интернет нужен для загрузки зависимостей. Task собирает контроллер перед каждой командой приложения, используя кеш Go. Сам контроллер работает локально; Python для его работы не нужен.

### Где взять identity

В BLE-сканере откройте manufacturer advertisement лампы LT-06. Identity — **первые шесть байтов manufacturer payload без двухбайтового Company ID**, записанные через двоеточие: `AA:BB:CC:DD:EE:FF`. Некоторые сканеры показывают Company ID отдельно; в этом случае не отбрасывайте два байта повторно.

Контроллер ищет лампу по этим данным. Identity не является UUID CoreBluetooth на Mac. Адрес устройства, показанный Android, используйте только после проверки, что он совпадает с identity в рекламе. В публичном проекте нет заранее заданного адреса лампы.

### Доступ к Bluetooth

Для отдельного CLI разрешите Bluetooth для Terminal или используемого терминального приложения в **System Settings → Privacy & Security → Bluetooth**. Запрос может появиться уже при `init`, `--help`, `send` или `dry-run`: библиотека создаёт объекты CoreBluetooth при загрузке. Это само по себе не означает сканирования, соединения или отправки команд. Task сохраняет контекст разрешений запустившего его терминала. Отсутствие `NSBluetoothAlwaysUsageDescription` в Warp по-прежнему может вызывать abort; при записанной проверке Terminal.app работал успешно. Отдельный app-runner не устанавливается.

## 2. Подключение лампы и Stream Deck

1. Включите питание лампы и Bluetooth на Mac.
2. В nRF Connect нажмите **Disconnect** и закройте MeRGBW на телефоне.
3. Запустите `task run` на том же Mac, где работает Stream Deck.
4. Оставьте Terminal открытым или свёрнутым; Mac не должен уходить в сон.
5. Откройте созданный **streamdeck-buttons.txt**.
6. Добавьте кнопку **System → Website**, скопируйте целиком нужный URL и включите **GET request in background**.

Сначала проверьте ON/OFF, затем RGB и яркость. Для остановки сервера нажмите **Ctrl+C**. После перезагрузки Mac запускайте сервер вручную; автозапуск не создаётся.

URL содержат локальный токен. Файлы `settings.json` и `streamdeck-buttons.txt` исключены из Git; сохраняйте их приватными. При обычном перезапуске токен и URL не меняются.

## Плагин Stream Deck

Версия **0.2.0.0** предоставляет семь Keypad-действий MeRGBW с общей панелью настройки для macOS **13.5+** и Stream Deck **7.1+**. Установщик содержит контроллер для Apple Silicon и Intel. Для использования готового пакета не нужны Terminal, Go, Node.js или отдельно запущенный сервер. Нужен manufacturer-data идентификатор лампы; его автоматический поиск не входит в эту возможность.

Откройте `com.obalunenko.mergbw.development.streamDeckPlugin`, добавьте действие MeRGBW и откройте его панель. При первом запуске откроется экран **Лампа и подключение**; после настройки он доступен по ссылке под настройками клавиши. Выберите EN или RU и способ настройки:

- **Ввести код лампы:** укажите шесть HEX-байтов через двоеточие, например `AA:BB:CC:DD:EE:FF`. Это первые шесть байтов manufacturer payload после Company ID, а не UUID CoreBluetooth. Просмотрите данные и примените их. Плагин создаст секрет и стандартные пресеты.
- **Импорт файлов:** выберите существующий `settings.json` и при необходимости `presets.json`, просмотрите изменения и подтвердите. Идентификатор, порт, секрет и выбранный пользовательский каталог сохраняются. Исходные файлы не меняются. Без файла пресетов сохраняется весь текущий каталог либо создаются стандартные пресеты, если каталога ещё нет. Отсутствующие стандартные ключи в импортированный каталог не добавляются.

Перед применением остановите прежний отдельный `sunset`. Одна командная ссылка не содержит идентификатора лампы. Из старых настроек плагина v1 можно явно сохранить корректные порт и секрет после ручного ввода идентификатора; подключение к внешнему серверу не включается. Конфликт порта не разрешает подключаться к чужому процессу или завершать его.

Все кнопки используют один собственный контроллер и одно BLE-соединение. Плагин запускает его после настройки и блокирует команды до подтверждения готовности и авторизации. Настройка, проверки и перезапуск не отправляют команд лампе. При запросе macOS разрешите Bluetooth; для повторного включения откройте **Системные настройки → Конфиденциальность и безопасность → Bluetooth** и найдите приложение, фактически показанное системой. Встроенное приложение **MeRGBW Controller** запускается отдельно и запрашивает собственное разрешение Bluetooth. Фактические результаты проверки разрешений записаны отдельно ниже.

| Действие | Назначение |
| --- | --- |
| On / Off | Одна явная команда питания |
| Color | Визуальный выбор или шесть HEX-цифр с необязательным `#`; по умолчанию FF5000 |
| Brightness | Целое число 0–100; по умолчанию 50 |
| Preset | Название из действующего каталога со стабильным сохранённым ID |
| Transition | Явные начальные/конечные RGB и яркость, целая длительность 1–60 секунд |
| Scene | Встроенная [сцена](#сцены) лампы или ID `80`–`93`; по умолчанию Disco |

**Настройки пресетов:** один список объединяет **Встроенные** и **Мои пресеты**. Выбор автоматически сохраняет назначение; ниже показаны цвет, яркость и эффект. Для встроенного пресета нажмите **Настроить копию**, для выбранного своего — **Изменить**, либо **+ Создать пресет**. Отдельный редактор показывает параметры выбранного эффекта. Смена типа сохраняет цвет, яркость, интервалы и порядок цветов черновика. **Библиотека** открывает общие пресеты для изменения и удаления; список загружается автоматически, при необходимости доступны следующие страницы. Обычные статические пресеты сохраняют прежнее поведение. Для динамических доступны:

| Эффект | Настройки |
| --- | --- |
| Смена цветов / Палитра | 2–16 упорядоченных цветов, яркость и 0,5–60 с на плавный переход; один проход или цикл с плавным возвращением к первому цвету |
| Стробоскоп | Цвет, яркость и отдельные интервалы включения/выключения по 0,25–60 с; один цикл или повтор |
| Дыхание | Цвет, минимальная/пиковая яркость и полный цикл нарастания/спада 1–120 с; один цикл или повтор |
| Свеча | Базовый цвет/яркость, сила мерцания и интервал 0,25–5 с; непрерывно или ограниченное время от 1 секунды до 1 часа |

Для нового пресета или копии нажмите **Создать и назначить…**, проверьте зафиксированные параметры и подтвердите **Создать и назначить**. Новый ID назначается этой клавише только после подтверждённого сохранения и обновления актуального каталога. При неизвестном исходе сохранения или ошибке обновления прежнее назначение остаётся: проверьте результат и при необходимости явно выберите сохранённый пресет. Правка общего пресета затрагивает все использующие его клавиши; проверьте и подтвердите **Применить изменения**. Переименование сохраняет назначения; удаление оставляет затронутые кнопки явно недоступными. Применение изменённых пресетов останавливает текущий эффект и перезапускает контроллер, сохраняя настройки лампы и секрет. Чтение, редактирование и сохранение не запускают эффект. Устаревший черновик не перезаписывает более новый каталог.

Нажмите кнопку динамического пресета для запуска, повторно — для остановки её текущего запуска. Выполняемый эффект можно остановить из настроек клавиши; в **Диагностике** доступны **Проверить статус эффекта** и **Остановить текущий эффект**. Обычная команда, поворот или нажатие ручки прерывают эффект; Off явно выключает свет. Остановка сохраняет последнее заданное состояние, включая выключенную фазу стробоскопа. После неопределённого ответа о запуске нажатие проверяет статус вместо слепого повторного запуска; остановку можно явно выбрать в панели. После перезапуска эффекты не возобновляются. Интервалы целевые и могут увеличиваться из-за задержек Bluetooth. Программные результаты и данные локального обновления записаны в [проверке функции](specs/008-configurable-preset-effects/validation.md); измеренную физическую форму эффекта они не подтверждают.

**Stream Deck+:** назначьте существующее действие **Brightness / Яркость** на ручку. Каждый щелчок по часовой стрелке добавляет один процентный пункт, против часовой — вычитает; пределы 0–100%. Сенсорная полоса показывает крупный процент и отдельный короткий статус. Это цель ручки, а не измеренная яркость лампы. Начальная цель берётся из сохранённого параметра яркости (по умолчанию 50%), а не считывается с лампы. Повороты меняют цель в текущем видимом сеансе; начальное значение сохраняйте через панель. Быстрые повороты объединяются в последнюю цель, одновременно выполняется не более одного запроса на ручку. Ошибка или неопределённый исход удаляет неотправленные изменения. Скрытие ручки, смена настроек или потеря готовности также удаляет их; после восстановления повторы не выполняются. Нажатие ручки отправляет **Off** и сохраняет целевой процент. Следующий поворот применяет цель и включает питание, в том числе при повороте к максимуму уже на 100%. Касание полосы и отпускание ручки команд не отправляют. Наблюдения пользователя для домашнего варианта записаны ниже.

**Плавный переход:** назначьте **Transition / Переход** на кнопку и сохраните начальные RGB/яркость, конечные RGB/яркость и длительность 1–60 секунд. По умолчанию FF5000 плавно меняется со 100% до 0% за 30 секунд. Контроллер сначала применяет явные начальные значения, затем изменяет их до конечных. Начальное состояние может измениться сразу; оно не считывается с лампы. **Принято** означает запуск фонового перехода, а не его завершение. После подтверждения запуска в **Диагностике** доступна кнопка **Отменить текущий переход**. **Проверить статус перехода** обновляет прогресс или итог; предварительно нажимать её для отмены не требуется. Новая допустимая команда, включая поворот ручки яркости, прерывает переход до собственного выполнения; уже начатая нативная запись должна вернуться первой. Отмена не добавляет Off. Конечная яркость 0% не является командой выключения питания. Задержка нативных операций может увеличить фактическое время. Закрытие или перезапуск плагина не возобновляет переход.

Цвет, яркость и пресеты также включают питание. Допустимые настройки клавиши сохраняются автоматически при изменении; само изменение не отправляет команды лампе. У каждой клавиши своё назначение. Подключение и диагностика вынесены на отдельные экраны, диагностические проверки выполняются явно. Прежние UUID, назначения, язык и пользовательские подписи/значки сохраняются. В экспортируемых назначениях нет секрета подключения и путей импортированных файлов. Профиль, перенесённый в другую установку, требует местной настройки лампы. Отсутствующий пресет остаётся недействительным до явного переназначения; другой пресет не подставляется.

Панель различает готовность контроллера, HTTP-авторизацию и Bluetooth-соединение. Соединение и сообщение **Команда передана** не подтверждают физическое состояние лампы. Ожидание показано в панели без значка ошибки на кнопке. Подтверждённая отправка показывает успех; отказ или неопределённый исход — предупреждение. Повторные нажатия занятой кнопки не добавляют команд. После тайм-аута или потери ответа исход может остаться неизвестным: осмотрите лампу перед новым осознанным нажатием. Нативная отмена кооперативна; начатая запись может завершиться до выхода процесса.

После устранения указанной причины откройте **Диагностика → Перезапустить контроллер**. Восстановление сохраняет конфигурацию и заново проверяет готовность, без воспроизведения команд. Если подтверждение сохранения потеряно, используйте проверку конфигурации без записи. Панель показывает **Сохранено**, **Не сохранено** или **Исход сохранения неизвестен**. Пока действующие данные нельзя прочитать, изменение конфигурации и команды лампе заблокированы.

Закрытие Stream Deck, отключение или перезапуск плагина останавливает его контроллер. Ожидающие действия и оставшиеся шаги отменяются без отдельной команды Off и автоматического продолжения. Системная служба и независимый автозапуск не создаются. Отдельный CLI и Website-кнопки GET/POST сохраняются; не запускайте конкурирующий контроллер на порту плагина.

Конфигурация лампы хранится в `~/Library/Application Support/com.obalunenko.mergbw`, вне заменяемого каталога плагина. Обновления сохраняют настройки, токены, пресеты и назначения. Файлы приватны; защищайте их копии как секреты. Перезапуск не перечитывает источники импорта: для изменения данных импортируйте обновлённую полную конфигурацию через панель.

Для разработки нужны **Go 1.27+**, **Node 24**, закреплённые инструменты проекта и macOS SDK. Программные проверки запускаются через `task plugin:check:software`. Полные `plugin:check` и `plugin:package` требуют нативного пакета с обеими архитектурами. По умолчанию используется `development` с локальными ad-hoc-подписями без учётных данных Apple. Установщик: `dist/com.obalunenko.mergbw.development.streamDeckPlugin`. Явный режим `PACKAGE_MODE=distribution` с Developer ID и нотариализацией остаётся необязательным и не входит в приёмку личной разработки. Точные команды сборки, разработки и явного link приведены в [quickstart](specs/007-bundled-plugin-controller/quickstart.md). Для локальной приёмки достаточно сборки `spike` для текущего Mac и явного link через закреплённый CLI. Этот пакет отделён от universal-установщика и по-прежнему отклоняется полными проверками упаковки. Достаточно локальной установки; скачивание установщика необязательно.

Проверки используют имитаторы HTTP, процессов и BLE, а нативные бинарники только собирают или исследуют без запуска worker. Они не устанавливают/link плагин и не управляют лампой. Диагностика содержит безопасные категории, длительности и ID запросов, исключая токены, полные командные URL, пути импорта и сырые нативные ошибки. Уровень журналирования SDK оставляйте INFO.

[Validation](specs/007-bundled-plugin-controller/validation.md) разделяет программные результаты и проверки локальной установки, разрешений Bluetooth, архитектур и LT-06. Developer ID, нотариализация и проверка скачанного установщика не входят в приёмку личной разработки. Прежняя [аппаратная проверка плагина](specs/006-streamdeck-control-plugin/hardware-verification.md) не подтверждает новую цепочку встроенных процессов и разрешений.

Текущая локальная версия принята для домашнего использования на проверенном Apple Silicon Mac/LT-06. Дополнительные ручные проверки разрешений, сбоев, сна, чистой установки и стресс-сценариев отложены по решению пользователя, а не объявлены пройденными. Защитные механизмы и автоматические тесты сохранены.

## Команды Task

Task собирает контроллер перед каждой командой приложения. Аргументы передаются после `--`. По умолчанию команды приложения и аппаратные тесты используют настройки из корня проекта; другую папку можно задать через `MERGBW_DATA_DIR` или переменную Task `DATA_DIR`.

```bash
task init -- --identity AA:BB:CC:DD:EE:FF
task run                         # alias: task serve
task urls
task send -- off
task send -- on
task send -- color FF5000
task send -- brightness 40
task send -- transition FF5000 100 FF5000 0 30
task send -- preset sunset
task dry-run -- on
task dry-run -- preset sunset
task inspect
task version
```

- `init` создаёт отсутствующие файлы, сохраняя существующие настройки и пресеты. Для новой конфигурации нужен `--identity`; `serve` тоже умеет инициализировать её с этим флагом. Другое значение флага не заменяет существующую identity: для смены лампы остановите сервер и явно измените `settings.json`.
- `send` обращается по HTTP к запущенному серверу. Выполняйте `task send` во втором терминале, оставив `task run` работающим.
- `inspect` обнаруживает лампу и подключается для просмотра рекламы/GATT, но не записывает управляющие пакеты. Перед ним остановите `serve`.
- `dry-run` показывает пакеты без подключения к лампе и отправки команд.
- `urls` обновляет и выводит ссылки кнопок.

Отдельная папка данных:

```bash
export MERGBW_DATA_DIR="$HOME/.config/mergbw"
task init -- --identity AA:BB:CC:DD:EE:FF
task run
```

Указывайте ту же папку для остальных команд. Храните её вне репозитория или добавьте в локальные исключения Git.

## Сцены

У лампы есть встроенные сцены (команда `0x06`). Запустить сцену можно из CLI, по HTTP или со Stream Deck:

```bash
./sunset send scene disco
./sunset dry-run scene 8a      # покажет 55 01 FF 06 01 A2, затем 55 06 FF 06 8A 14
```

HTTP: `GET|POST /<token>/scene/<slug|ID>`. Действие Stream Deck **Scene** хранит одну сцену на клавишу. Сцена сначала включает лампу и останавливает запущенный программный эффект или переход. `./sunset urls` выводит ссылку для каждой именованной сцены.

Подробности — в [отчёте проверки сцен](specs/009-full-command-scene-support/hardware-verification.md).

## HTTP API

Сервер слушает только IPv4 loopback. Команды принимают **GET или POST без тела и query-параметров**. GET предусмотрен для фонового действия Website в Stream Deck.

| Маршрут | Действие |
|---|---|
| `/health` | Состояние сервиса и BLE-соединения, без токена |
| `/<token>/presets` | Только GET: авторизованный каталог ID/названий, без BLE-вызовов |
| `/<token>/on` | Включить |
| `/<token>/off` | Выключить |
| `/<token>/color/FF5000` | Задать RGB шестью HEX-цифрами |
| `/<token>/brightness/40` | Яркость целым числом 0–100 |
| `/<token>/preset/sunset` | Применить пресет |
| `/<token>/scene/disco` | Запустить встроенную [сцену](#сцены) по slug или ID `80`–`93` |

Используйте готовые URL из файла. Цвет, яркость, пресет и сцена сначала отправляют включение лампы. HEAD не выполняет команды управления.

`sent: true` означает завершённую BLE-запись, а `physical_state_verified` всегда остаётся `false`. Поле `bluetooth_connected` в `/health` описывает соединение, а не реальное включение или цвет лампы. Некоторые вызовы CoreBluetooth ожидают внутреннего тайм-аута: HTTP-тайм-аут не гарантирует мгновенную отмену уже начавшейся записи.

## Логи

Контроллер пишет структурированные текстовые логи через Go `log/slog` в **stderr**, с временем и уровнем события. Маршрут команды указан в `command`, идентификатор запроса — в `request_id`; для BLE записываются `packet_hex`, результаты, повторы, ошибки и `duration_ms`. Запрос можно проследить от `command.received` через `packet.sent` до `command.sent`; ошибки и повторы отмечены событиями `command.failed` и `command.retry`.

Событие `bluetooth.connected` описывает реально подключённую лампу: `identity`, `device_name`, `device_address`, `service_uuid` и `write_uuid`. Identity в `service.started` обозначает только устройство из настроек. Ни одно из этих событий не подтверждает реальное включение или цвет лампы.

Иллюстративный пример подключения; идентификаторы вымышлены:

```text
time=2026-01-01T12:00:00.000Z level=INFO msg=bluetooth.connected identity=AA:BB:CC:DD:EE:FF device_name=LT-06 device_address=00000000-0000-0000-0000-000000000000 service_uuid=0000fff0-0000-1000-8000-00805f9b34fb write_uuid=0000fff3-0000-1000-8000-00805f9b34fb
```

Успешные запросы `/health` не засоряют логи. Токены доступа и полные URL команд в них не записываются. По умолчанию логи видны в Terminal; для одновременной записи в файл запустите из папки проекта:

```bash
task run 2>&1 | tee -a sunset.log
```

`*.log` исключены из Git. Файл содержит идентификаторы устройства и историю команд. Требования к разрешению Bluetooth в macOS не меняются.

## Настройки и пресеты

В `settings.json` находятся `device_identity`, `port` и `access_token`. Меняйте настройки при остановленном сервере. В `presets.json` каждый стабильный ключ задаёт `label`, `rgb` — три числа 0–255, и `brightness` — число 0–100.

| Пресет | RGB | Яркость |
|---|---|---|
| `sunset` — Закат | 255, 80, 0 | 60% |
| `night` — Ночь | 40, 60, 255 | 25% |
| `alarm` — Тревога | 255, 0, 0 | 70% |
| `magic` — Магия | 160, 0, 255 | 45% |
| `forest` — Лес | 20, 180, 60 | 40% |
| `white` — Белый RGB | 255, 255, 255 | 50% |

`white` смешивает RGB-каналы; отдельный белый режим лампы не используется. Остановите сервер, измените JSON и перезапустите его. При неизменных ключах, порте и токене старые URL сохраняются. Ссылки новых пресетов появятся в `streamdeck-buttons.txt`.

### Переход с Python

Остановите Python-сервер, скопируйте его `settings.json` и `presets.json` рядом с Go-бинарником, выполните `./sunset init` и `./sunset serve`. Токен, маршруты и ключи пресетов сохраняются, поэтому прежние кнопки Stream Deck продолжат работать. На настроенном порту должен работать один сервер.

## Разработка и проверка

CLI находится в `cmd/sunset`, протокол — в `internal/protocol`, Bluetooth-логика с синхронными интерфейсами — в `internal/ble`, адаптер TinyGo — в `internal/ble/native`, очередь команд — в `internal/controller`, HTTP — в `internal/bridge`, настройки — в `internal/config`. Импорт `internal/ble/native` может инициализировать CoreBluetooth.

Установите закреплённые инструменты разработки и используйте команды проекта:

```bash
task tools
task --list
task build
task test:core
task test:race
task workflows:test
```

`task tools` вызывает Make-bootstrap, устанавливающий инструменты из `tools/*/go.mod` командой `go install tool`. Если Task ещё не установлен, выполните `go tool -modfile=tools/task/go.mod task tools`; прямой `make tools` также доступен для начальной установки. Task 3.54.0 закреплён в `tools/task/go.mod`, зависимости — в `tools/task/go.sum`. При необходимости добавьте `$(go env GOPATH)/bin` в `PATH` либо запускайте `go tool -modfile=tools/task/go.mod task --list` напрямую. Контроллер и оба модуля инструментов требуют Go 1.27.0 или новее. Go автоматически загрузит нужный toolchain, если не задан `GOTOOLCHAIN=local`.

`task workflows:test` проверяет порядок Task-команд, передачу аргументов и папки настроек, возврат ошибок и аппаратные предусловия с записывающими исполняемыми файлами, без native Bluetooth.

Go-тесты используют проверки Testify 1.11.1 и моки интерфейсов Uber Mock 0.6.0. Тестовые библиотеки находятся в корневом `go.mod`, генератор закреплён отдельно в `tools/mockgen/go.mod` (Go 1.27.0). После изменения интерфейсов выполните `task mocks:generate` и добавьте сгенерированные `mock_*_test.go` в коммит. Генерация использует закреплённый модуль и не зависит от глобальной версии mockgen.

`task test:core` и `task test:race` включают BLE-backend со сгенерированными моками адаптера и устройства. Они не импортируют native-адаптер и не требуют оборудования или разрешений Bluetooth. Обычная команда `task test` также исключает аппаратные тесты.

Интеграционные тесты реального оборудования требуют build tag `hardware` и запускаются только локально отдельной командой. Остановите `task run` и отключите другие клиенты. Если настройки находятся в корне проекта:

```bash
task test:hardware
```

Команда запрещает запуск в CI и требует settings.json и presets.json в выбранной папке. Для другой папки выполните `MERGBW_DATA_DIR=/absolute/path/to/lamp-config task test:hardware`. `TestHardwareLamp` проверяет FFF0/FFF3, затем формирует и отправляет реальные команды через контроллер и native BLE-backend на одном постоянном соединении. Последовательность задаёт белый цвет и яркость 100%, проверяет отправку OFF/ON, красного/зелёного/синего, яркости 0/50/100%, всех пресетов из локальных настроек в порядке идентификаторов и завершающего OFF. После каждой успешной команды тест ждёт две секунды и выводит ожидаемый визуальный эффект. При первой ошибке последовательность останавливается и соединение освобождается; завершающий OFF достигается только при успехе предыдущих шагов. Общий тайм-аут — 15 минут; отдельные операции используют кооперативный контекст на 35 секунд.

PASS подтверждает соединение/GATT и отправку команд, без считывания физического состояния. Наблюдайте за лампой и отдельно записывайте устройство, команду и фактический эффект; идентификаторы устройства и секреты храните в локальных записях. При [проверке 2026-10-21](specs/002-ble-command-execution/hardware-verification.md) все команды запускались отдельными фильтрованными вызовами с подтверждениями пользователя; вся последовательность без остановок не запускалась. Изменения яркости сравнивались визуально, без калиброванных измерений. Импорт native-пакета может запросить разрешение Bluetooth на macOS. Если Warp завершается из-за отсутствия `NSBluetoothAlwaysUsageDescription`, запустите тест из Terminal.app: в этой сессии такой запуск прошёл успешно. Аппаратные тесты исключены из обычных тестов, race-проверок, `task check` и CI; компиляция или пропущенный тест не подтверждают проверку оборудования.

[CI workflow](.github/workflows/ci.yml) выполняет тесты, проверки гонок основной логики, vet и сборку на Linux с Go 1.27.x и текущей стабильной версией Go. Отдельная задача macOS компилирует CoreBluetooth-backend с CGO; она не запускает контроллер или BLE-тесты. Ни эти проверки, ни успешная сборка на Mac не проверяют реальную лампу. Физические результаты получены отдельной локальной проверкой, описанной выше.

Если Bluetooth-backend сообщает, что процесс требует перезапуска, остановите сервер и запустите его снова. Повторные HTTP-команды не восстанавливают адаптер, помеченный как непригодный после неопределённого результата операции.

### Spec Kit

Для работы со спецификациями нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
task speckit:install
task speckit:update:check
task speckit:update:test
```

В Taskfile.yml закреплены Spec Kit 1.1.3, Companion 0.25.0, Brownfield 1.0.0, Bugfix 1.1.0 и локальное расширение feature-numbering 1.0.0. Установщик ставит Specify CLI через `uv tool install`, затем все интеграции агентов из `SPECKIT_INTEGRATIONS` (по умолчанию `codex claude`: skills Codex в `.agents/skills/`, skills Claude Code в `.claude/skills/`) и регистрирует все четыре расширения проекта для каждой из них. Первая интеграция используется по умолчанию и задаёт написание команд в общих скриптах Spec Kit. Другие агенты выбираются, например, так: `SPECKIT_INTEGRATIONS="claude gemini" task speckit:install`; список поддерживаемых ключей показывает `specify integration list`. Существующая инициализация Spec Kit сохраняется; новый проект инициализируется для интеграции по умолчанию. После установки перезапустите агента, чтобы загрузить созданные skills.

Инструкции для агентов находятся в `AGENTS.md`; `CLAUDE.md` только импортирует его для Claude Code.

Каталоги новых возможностей имеют вид `specs/NNN-feature-name`, начиная с `001`. Обязательный hook `before_specify` выбирает следующий номер для стандартного Specify и Companion. Исходники расширения находятся в `.speckit/feature-numbering/`.

Проверка обновлений показывает установленные версии, расхождения с закреплёнными версиями и новые релизы, не устанавливая обновления. При наличии CLI VS Code или Cursor также проверяется расширение Companion для редактора. Чтобы применить обновление, измените версии в Taskfile.yml и повторите `task speckit:install`. Команда `task speckit:update:test` запускает регрессионные тесты проверки обновлений локально без сети.
