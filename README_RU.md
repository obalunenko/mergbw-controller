# MeRGBW Controller: LT-06 и Stream Deck

Локальный контроллер на Go для **MeRGBW LT-06**. Один процесс `sunset` принимает HTTP-команды от Stream Deck, последовательно отправляет их по BLE и сохраняет соединение с лампой. Адрес по умолчанию — `127.0.0.1:18765`.

[English documentation](README.md)

## Совместимость и статус проверки

- Целевое устройство — LT-06: advertising service `3519`, GATT service `FFF0`, запись в `FFF3`.
- **Go BLE-путь проверен на одном LT-06 под macOS 2026-10-21:** ON/OFF, белый и RGB-цвета, яркость 0/50/100% и все шесть локальных пресетов с визуальным подтверждением пользователя. См. [отчёт аппаратной проверки](specs/002-ble-command-execution/hardware-verification.md). Ранее пакеты ON/OFF также проверялись через nRF Connect.
- Проверка относится к этому устройству и окружению. Совместимость других устройств из приложения MeRGBW не подтверждена.
- Считывание реального состояния, музыка, фирменные анимации и плавные переходы не реализованы.

## 1. Сборка на macOS

Нужны **Go 1.25.0+** с [go.dev/dl](https://go.dev/dl/) и **Xcode Command Line Tools** с clang и macOS SDK. Если инструментов Apple нет, установите их и дождитесь завершения:

```bash
xcode-select --install
```

Используется обычный компилятор Go и библиотека `tinygo.org/x/bluetooth v0.16.0`. Компилятор TinyGo не требуется. Backend macOS использует CoreBluetooth через CGO, поэтому сборка выполняется на Mac — см. [официальные требования библиотеки](https://github.com/tinygo-org/bluetooth/blob/v0.16.0/README.md#macos).

```bash
git clone https://github.com/obalunenko/mergbw-controller.git
cd mergbw-controller
go tool -modfile=tools/task/go.mod task tools
task setup -- --identity AA:BB:CC:DD:EE:FF
task run
```

Замените пример identity значением из рекламы своей лампы, как описано ниже. `task setup` загружает модули приложения, собирает `sunset` и создаёт отсутствующие настройки. Существующие настройки сохраняются. Закреплённый модуль Task требует Go 1.27.0; при необходимости Go автоматически загрузит этот toolchain. Go и Xcode установите отдельно; системная служба не создаётся.

Отдельные шаги подготовки:

```bash
task deps
task build
task init -- --identity AA:BB:CC:DD:EE:FF
```

Интернет нужен для загрузки зависимостей. Task собирает контроллер перед каждой командой приложения, используя кеш Go. Сам контроллер работает локально; Python для его работы не нужен.

### Где взять identity

В BLE-сканере откройте manufacturer advertisement лампы LT-06. Identity — **первые шесть байтов manufacturer payload без двухбайтового Company ID**, записанные через двоеточие: `AA:BB:CC:DD:EE:FF`. Некоторые сканеры показывают Company ID отдельно; в этом случае не отбрасывайте два байта повторно.

Контроллер ищет лампу по этим данным. Identity не является UUID CoreBluetooth на Mac. Адрес устройства, показанный Android, используйте только после проверки, что он совпадает с identity в рекламе. В публичном проекте нет заранее заданного адреса лампы.

### Доступ к Bluetooth

Разрешите Bluetooth для Terminal или используемого терминального приложения в **System Settings → Privacy & Security → Bluetooth**. Запрос может появиться уже при `init`, `--help`, `send` или `dry-run`: библиотека создаёт объекты CoreBluetooth при загрузке. Это само по себе не означает сканирования, соединения или отправки команд. Task сохраняет контекст разрешений запустившего его терминала. Отсутствие `NSBluetoothAlwaysUsageDescription` в Warp по-прежнему может вызывать abort; при записанной проверке Terminal.app работал успешно. Отдельный app-runner не устанавливается.

## 2. Подключение лампы и Stream Deck

1. Включите питание лампы и Bluetooth на Mac.
2. В nRF Connect нажмите **Disconnect** и закройте MeRGBW на телефоне.
3. Запустите `task run` на том же Mac, где работает Stream Deck.
4. Оставьте Terminal открытым или свёрнутым; Mac не должен уходить в сон.
5. Откройте созданный **streamdeck-buttons.txt**.
6. Добавьте кнопку **System → Website**, скопируйте целиком нужный URL и включите **GET request in background**.

Сначала проверьте ON/OFF, затем RGB и яркость. Для остановки сервера нажмите **Ctrl+C**. После перезагрузки Mac запускайте сервер вручную; автозапуск не создаётся.

URL содержат локальный токен. Файлы `settings.json` и `streamdeck-buttons.txt` исключены из Git; сохраняйте их приватными. При обычном перезапуске токен и URL не меняются.

## Плагин Stream Deck

Версия **0.1.0.0** предоставляет пять Keypad-действий MeRGBW с общей панелью Property Inspector. Требуются macOS **13.5+**, Stream Deck **7.1+** и подготовленный локальный контроллер `sunset`, запущенный по инструкции выше. Для сборки нужны **Node 24**, npm и инструменты Task проекта. Плагин использует HTTP-мост, сам не запускает контроллер и не создаёт BLE-соединение. Прежние Website-кнопки работают без миграции.

Соберите установщик из корня проекта:

```sh
make tools
task plugin:deps
task plugin:package
```

Откройте `dist/com.obalunenko.mergbw.streamDeckPlugin` в Stream Deck и перетащите **MeRGBW → On** и **Off** на клавиши. В панели любой кнопки выберите EN или RU и импортируйте одну существующую ссылку из приватного `streamdeck-buttons.txt`. Импорт извлекает порт и токен без выполнения команды и не переносит её назначение на выбранную кнопку. Стандартный порт — 18765. Подключение общее для всех кнопок; пустое поле замены токена сохраняет прежний. Поля ссылки и пароля очищаются после отправки, сохранённый токен не отображается.

После ручного изменения порта или токена нажмите **Save / Сохранить** рядом с **Проверить подключение**. Проверка использует сохранённое подключение; пустое поле замены токена оставляет прежний токен.

**Проверить подключение** показывает сервис, авторизацию и Bluetooth раздельно. Health не подтверждает токен; его проверяет авторизованный каталог. Отключённый Bluetooth не означает выключенную лампу. Проверки и обновление списка не отправляют команд управления. HTTP-запросы ограничены `127.0.0.1`, без proxy, перенаправлений и автоматических повторов; файлы интерфейса включены в пакет и работают офлайн.

Если проверка или обновление пресетов не завершились вовремя, проверьте `sunset` и порт, затем повторите проверку или обновление. Такой тайм-аут не означает отправку команды лампе. Во время сохранения можно продолжать редактирование; ошибка сохранения остаётся видимой до успешного сохранения соответствующей настройки.

| Действие | Назначение |
| --- | --- |
| On / Off | Одна явная команда питания |
| Color | Визуальный выбор или шесть HEX-цифр с необязательным `#`; по умолчанию FF5000 |
| Brightness | Целое число 0–100, ползунок или поле; по умолчанию 50 |
| Preset | Название из действующего каталога; сохраняется стабильный ID |

Цвет, яркость и пресеты также включают питание. Сохраняйте назначение каждой кнопки отдельно. Копии редактируются независимо, подключение не попадает в экспортируемые настройки действий. После импорта профиля в другую установку настройте общее подключение там. Пользовательские подписи и значки хоста имеют приоритет над оформлением по умолчанию.

После изменения пресетов перезапустите `sunset` и нажмите **Обновить пресеты**. Переименование сохраняет выбранный ID, одинаковые названия различаются ID. Известный удалённый пресет блокирует кнопку и требует нового выбора. Ошибка или отсутствие поддержки списка не подменяет пресет; существующий корректный ID можно осознанно отправить. Старый контроллер нужно обновить для каталога, при этом совместимые команды питания, цвета и яркости доступны.

Короткая стандартная attention-индикация при нажатии означает обработку, в панели указано **Выполняется**. Повторные нажатия занятой кнопки не добавляют команд. Успех означает **Команда передана**, состояние лампы не проверено. При отказе панель показывает безопасное объяснение и следующий шаг. Неизвестный исход и завершение 45-секундного ожидания допускают поздний физический эффект: осмотрите лампу перед новым осознанным нажатием. Этот лимит не обещает отмену нативной BLE-записи. Перезапуск, изменение настроек и ошибки не воспроизводят команды.

Журналы плагина находятся в `logs/` установленного каталога, для linked-разработки — в `streamdeck/com.obalunenko.mergbw.sdPlugin/logs/`. Ищите тип действия, исход/категорию, длительность и десятичный ID запроса. INFO задаётся до подключения SDK; не включайте TRACE или журналирование payload. Токены, полные командные URL и сырые ошибки сервиса исключены. Если сервис недоступен, запустите `sunset` и проверьте порт; при отказе доступа замените общий токен; при сбое backend проверьте контроллер/Bluetooth перед повтором.

| Локальная команда | Назначение |
| --- | --- |
| `task plugin:deps` | Установить npm-зависимости по lockfile |
| `task plugin:lint` | Проверить lint и форматирование |
| `task plugin:typecheck` | Проверить типы backend и панели |
| `task plugin:test` | Синтетические тесты без хоста и Bluetooth |
| `task plugin:build` | Собрать runtime и панель |
| `task plugin:validate` | Проверить собранный плагин |
| `task plugin:check` | Последовательно lint, типы, тесты, сборка, validation и состав пакета |
| `task plugin:package` | Выполнить check и заменить установщик в корневом dist |
| `task plugin:link` | Явно собрать/link вместо установки |
| `task plugin:watch` | Явно пересобирать/перезапускать уже linked-плагин |
| `task plugin:mock -- --catalog renamed` | Явно запустить имитатор на порту 18766 |
| `task workflows:test` | Проверить порядок Task с fake executables |

Проверки не устанавливают/link плагин, не запускают сервис и не отправляют аппаратные команды. Не устанавливайте и не связывайте один UUID одновременно. Назначение `make tools` и прежнего Linux Go `task check` сохранено. [Quickstart плагина](specs/006-streamdeck-control-plugin/quickstart.md) описывает варианты каталога/ошибок имитатора, приёмку хоста и отдельные аппаратные шаги. Фактические результаты и явные исключения приёмки перечислены в [validation](specs/006-streamdeck-control-plugin/validation.md) и [physical verification](specs/006-streamdeck-control-plugin/hardware-verification.md). На одной LT-06 владелец проверил On/Off, RGB FF5000, яркость 25/75 и sunset из плагина на macOS 27.0.1 со Stream Deck 7.6.0; автоматического чтения состояния лампы это не добавляет. Сборка и имитация не подтверждают состояние лампы.

Для linked-разработки нужен режим разработчика Stream Deck: явно включите его командой `streamdeck/node_modules/.bin/streamdeck dev` перед `task plugin:link` или `task plugin:watch`. Успешное завершение CLI restart само по себе не подтверждает загрузку: проверьте пять действий MeRGBW и запись `plugin.ready` в журнале. Для перехода с linked-копии на обычный установщик выполните `streamdeck/node_modules/.bin/streamdeck unlink com.obalunenko.mergbw` без `--delete`, затем откройте установщик. Файлы репозитория при unlink сохраняются.

## Команды Task

Task собирает контроллер перед каждой командой приложения. Аргументы передаются после `--`. По умолчанию команды приложения и аппаратные тесты используют настройки из корня проекта; другую папку можно задать через `MERGBW_DATA_DIR` или переменную Task `DATA_DIR`.

```bash
task init -- --identity AA:BB:CC:DD:EE:FF
task run                         # alias: task serve
task urls
task send -- off
task send -- on
task send -- color FF5000
task send -- brightness 40
task send -- preset sunset
task dry-run -- on
task dry-run -- preset sunset
task inspect
task version
```

- `init` создаёт отсутствующие файлы, сохраняя существующие настройки и пресеты. Для новой конфигурации нужен `--identity`; `serve` тоже умеет инициализировать её с этим флагом. Другое значение флага не заменяет существующую identity: для смены лампы остановите сервер и явно измените `settings.json`.
- `send` обращается по HTTP к запущенному серверу. Выполняйте `task send` во втором терминале, оставив `task run` работающим.
- `inspect` обнаруживает лампу и подключается для просмотра рекламы/GATT, но не записывает управляющие пакеты. Перед ним остановите `serve`.
- `dry-run` показывает пакеты без подключения к лампе и отправки команд.
- `urls` обновляет и выводит ссылки кнопок.

Отдельная папка данных:

```bash
export MERGBW_DATA_DIR="$HOME/.config/mergbw"
task init -- --identity AA:BB:CC:DD:EE:FF
task run
```

Указывайте ту же папку для остальных команд. Храните её вне репозитория или добавьте в локальные исключения Git.

## HTTP API

Сервер слушает только IPv4 loopback. Команды принимают **GET или POST без тела и query-параметров**. GET предусмотрен для фонового действия Website в Stream Deck.

| Маршрут | Действие |
|---|---|
| `/health` | Состояние сервиса и BLE-соединения, без токена |
| `/<token>/presets` | Только GET: авторизованный каталог ID/названий, без BLE-вызовов |
| `/<token>/on` | Включить |
| `/<token>/off` | Выключить |
| `/<token>/color/FF5000` | Задать RGB шестью HEX-цифрами |
| `/<token>/brightness/40` | Яркость целым числом 0–100 |
| `/<token>/preset/sunset` | Применить пресет |

Используйте готовые URL из файла. Цвет, яркость и пресет сначала отправляют включение лампы. HEAD не выполняет команды управления.

`sent: true` означает завершённую BLE-запись, а `physical_state_verified` всегда остаётся `false`. Поле `bluetooth_connected` в `/health` описывает соединение, а не реальное включение или цвет лампы. Некоторые вызовы CoreBluetooth ожидают внутреннего тайм-аута: HTTP-тайм-аут не гарантирует мгновенную отмену уже начавшейся записи.

## Логи

Контроллер пишет структурированные текстовые логи через Go `log/slog` в **stderr**, с временем и уровнем события. Маршрут команды указан в `command`, идентификатор запроса — в `request_id`; для BLE записываются `packet_hex`, результаты, повторы, ошибки и `duration_ms`. Запрос можно проследить от `command.received` через `packet.sent` до `command.sent`; ошибки и повторы отмечены событиями `command.failed` и `command.retry`.

Событие `bluetooth.connected` описывает реально подключённую лампу: `identity`, `device_name`, `device_address`, `service_uuid` и `write_uuid`. Identity в `service.started` обозначает только устройство из настроек. Ни одно из этих событий не подтверждает реальное включение или цвет лампы.

Иллюстративный пример подключения; идентификаторы вымышлены:

```text
time=2026-01-01T12:00:00.000Z level=INFO msg=bluetooth.connected identity=AA:BB:CC:DD:EE:FF device_name=LT-06 device_address=00000000-0000-0000-0000-000000000000 service_uuid=0000fff0-0000-1000-8000-00805f9b34fb write_uuid=0000fff3-0000-1000-8000-00805f9b34fb
```

Успешные запросы `/health` не засоряют логи. Токены доступа и полные URL команд в них не записываются. По умолчанию логи видны в Terminal; для одновременной записи в файл запустите из папки проекта:

```bash
task run 2>&1 | tee -a sunset.log
```

`*.log` исключены из Git. Файл содержит идентификаторы устройства и историю команд. Требования к разрешению Bluetooth в macOS не меняются.

## Настройки и пресеты

В `settings.json` находятся `device_identity`, `port` и `access_token`. Меняйте настройки при остановленном сервере. В `presets.json` каждый стабильный ключ задаёт `label`, `rgb` — три числа 0–255, и `brightness` — число 0–100.

| Пресет | RGB | Яркость |
|---|---|---|
| `sunset` — Закат | 255, 80, 0 | 60% |
| `night` — Ночь | 40, 60, 255 | 25% |
| `alarm` — Тревога | 255, 0, 0 | 70% |
| `magic` — Магия | 160, 0, 255 | 45% |
| `forest` — Лес | 20, 180, 60 | 40% |
| `white` — Белый RGB | 255, 255, 255 | 50% |

`white` смешивает RGB-каналы; отдельный белый режим лампы не используется. Остановите сервер, измените JSON и перезапустите его. При неизменных ключах, порте и токене старые URL сохраняются. Ссылки новых пресетов появятся в `streamdeck-buttons.txt`.

### Переход с Python

Остановите Python-сервер, скопируйте его `settings.json` и `presets.json` рядом с Go-бинарником, выполните `./sunset init` и `./sunset serve`. Токен, маршруты и ключи пресетов сохраняются, поэтому прежние кнопки Stream Deck продолжат работать. На настроенном порту должен работать один сервер.

## Разработка и проверка

CLI находится в `cmd/sunset`, протокол — в `internal/protocol`, Bluetooth-логика с синхронными интерфейсами — в `internal/ble`, адаптер TinyGo — в `internal/ble/native`, очередь команд — в `internal/controller`, HTTP — в `internal/bridge`, настройки — в `internal/config`. Импорт `internal/ble/native` может инициализировать CoreBluetooth.

Установите закреплённые инструменты разработки и используйте команды проекта:

```bash
task tools
task --list
task build
task test:core
task test:race
task workflows:test
```

`task tools` вызывает Make-bootstrap, устанавливающий инструменты из `tools/*/go.mod` командой `go install tool`. Если Task ещё не установлен, выполните `go tool -modfile=tools/task/go.mod task tools`; прямой `make tools` также доступен для начальной установки. Task 3.54.0 закреплён в `tools/task/go.mod`, зависимости — в `tools/task/go.sum`. При необходимости добавьте `$(go env GOPATH)/bin` в `PATH` либо запускайте `go tool -modfile=tools/task/go.mod task --list` напрямую. Модуль инструмента Task требует Go 1.27.0; Go автоматически загрузит нужный toolchain, если не задан `GOTOOLCHAIN=local`. Требование контроллера остаётся Go 1.25.0+.

`task workflows:test` проверяет порядок Task-команд, передачу аргументов и папки настроек, возврат ошибок и аппаратные предусловия с записывающими исполняемыми файлами, без native Bluetooth.

Go-тесты используют проверки Testify 1.11.1 и моки интерфейсов Uber Mock 0.6.0. Тестовые библиотеки находятся в корневом `go.mod`, генератор закреплён отдельно в `tools/mockgen/go.mod` (Go 1.25.0). После изменения интерфейсов выполните `task mocks:generate` и добавьте сгенерированные `mock_*_test.go` в коммит. Генерация использует закреплённый модуль и не зависит от глобальной версии mockgen.

`task test:core` и `task test:race` включают BLE-backend со сгенерированными моками адаптера и устройства. Они не импортируют native-адаптер и не требуют оборудования или разрешений Bluetooth. Обычная команда `task test` также исключает аппаратные тесты.

Интеграционные тесты реального оборудования требуют build tag `hardware` и запускаются только локально отдельной командой. Остановите `task run` и отключите другие клиенты. Если настройки находятся в корне проекта:

```bash
task test:hardware
```

Команда запрещает запуск в CI и требует settings.json и presets.json в выбранной папке. Для другой папки выполните `MERGBW_DATA_DIR=/absolute/path/to/lamp-config task test:hardware`. `TestHardwareLamp` проверяет FFF0/FFF3, затем формирует и отправляет реальные команды через контроллер и native BLE-backend на одном постоянном соединении. Последовательность задаёт белый цвет и яркость 100%, проверяет отправку OFF/ON, красного/зелёного/синего, яркости 0/50/100%, всех пресетов из локальных настроек в порядке идентификаторов и завершающего OFF. После каждой успешной команды тест ждёт две секунды и выводит ожидаемый визуальный эффект. При первой ошибке последовательность останавливается и соединение освобождается; завершающий OFF достигается только при успехе предыдущих шагов. Общий тайм-аут — 15 минут; отдельные операции используют кооперативный контекст на 35 секунд.

PASS подтверждает соединение/GATT и отправку команд, без считывания физического состояния. Наблюдайте за лампой и отдельно записывайте устройство, команду и фактический эффект; идентификаторы устройства и секреты храните в локальных записях. При [проверке 2026-10-21](specs/002-ble-command-execution/hardware-verification.md) все команды запускались отдельными фильтрованными вызовами с подтверждениями пользователя; вся последовательность без остановок не запускалась. Изменения яркости сравнивались визуально, без калиброванных измерений. Импорт native-пакета может запросить разрешение Bluetooth на macOS. Если Warp завершается из-за отсутствия `NSBluetoothAlwaysUsageDescription`, запустите тест из Terminal.app: в этой сессии такой запуск прошёл успешно. Аппаратные тесты исключены из обычных тестов, race-проверок, `task check` и CI; компиляция или пропущенный тест не подтверждают проверку оборудования.

[CI workflow](.github/workflows/ci.yml) выполняет тесты, проверки гонок основной логики, vet и сборку на Linux с Go 1.25.x и текущей стабильной версией Go. Отдельная задача macOS компилирует CoreBluetooth-backend с CGO; она не запускает контроллер или BLE-тесты. Ни эти проверки, ни успешная сборка на Mac не проверяют реальную лампу. Физические результаты получены отдельной локальной проверкой, описанной выше.

Если Bluetooth-backend сообщает, что процесс требует перезапуска, остановите сервер и запустите его снова. Повторные HTTP-команды не восстанавливают адаптер, помеченный как непригодный после неопределённого результата операции.

### Spec Kit

Для работы со спецификациями нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
task speckit:install
task speckit:update:check
task speckit:update:test
```

В Taskfile.yml закреплены Spec Kit 1.1.3, Companion 0.25.0, Brownfield 1.0.0, Bugfix 1.1.0 и локальное расширение feature-numbering 1.0.0. Установщик ставит Specify CLI через `uv tool install`, затем все четыре расширения проекта со skills для Codex. Существующая инициализация Spec Kit сохраняется; новый проект автоматически инициализируется для Codex. После установки перезапустите Codex, чтобы загрузить созданные skills.

Каталоги новых возможностей имеют вид `specs/NNN-feature-name`, начиная с `001`. Обязательный hook `before_specify` выбирает следующий номер для стандартного Specify и Companion. Исходники расширения находятся в `.speckit/feature-numbering/`.

Проверка обновлений показывает установленные версии, расхождения с закреплёнными версиями и новые релизы, не устанавливая обновления. При наличии CLI VS Code или Cursor также проверяется расширение Companion для редактора. Чтобы применить обновление, измените версии в Taskfile.yml и повторите `task speckit:install`. Команда `task speckit:update:test` запускает регрессионные тесты проверки обновлений локально без сети.
