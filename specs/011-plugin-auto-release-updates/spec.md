# Feature Specification: Авторелиз плагина и предложение обновления

**Feature Directory**: `specs/011-plugin-auto-release-updates`

**Feature Branch**: `feature/plugin-auto-release-updates` (от `master` на `7e63cd0`).

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: «так же я хочу чтобы при выпуске тага был авторелиз плагина который можно установить на стримдек и все будет работать, в релизе релизноутс изменений всех. и при выходе новой версии плагина установленный плагин на стрим деке должен предложить установить новую версию из релиза»

## Контекст: что уже есть

Тег `vX.Y.Z` уже запускает релиз: архивы контроллера, установщик плагина
`com.obalunenko.mergbw.development.streamDeckPlugin`, `SHA256SUMS` и
сгенерированные заметки о коммитах с прошлого тега. Пробелы, которые закрывает
эта функция:

1. Версия плагина задана вручную в манифесте (`0.2.0.0`) и не связана с тегом,
   поэтому установленный плагин не может понять, новее ли релиз.
2. Установщик собран как локальная development-сборка с ad-hoc подписями;
   скачанный из релиза файл не проверялся на «установил — и всё работает».
3. Установленный плагин никак не узнаёт о выходе новой версии.

## Clarifications

### Session 2026-10-25

- Q: Как подписывать установщик, скачиваемый из релиза? → A: Ad-hoc подписи плюс документированный однократный шаг (снять карантин или разрешить в Privacy & Security); без Developer ID и нотаризации.
- Q: Где плагин сообщает о новой версии? → A: Полное предложение в панели действия плюс одно системное уведомление macOS на каждую новую версию.
- Q: Какая версия у локальной сборки? → A: `X.Y.Z.N`: `X.Y.Z` из последнего тега, а `N` увеличивается с каждой локальной сборкой. Релиз всегда `X.Y.Z.0`. Локальная сборка новее своего релиза, но старше следующего, поэтому плагин предлагает следующий релиз.
- Q: Ставит ли плагин новую версию сам, без нажатия владельца? → A: Нет. Уведомление и баннер с кнопкой «Установить»; по нажатию установщик скачивается, проверяется и открывается в окне установки Stream Deck, которое нужно подтвердить. Тихой или самопроизвольной установки нет (FR-008).
- Q: Нужно ли предлагать пререлизы? → A: Нет, только стабильные релизы. Пререлиз ставится вручную; позже вышедшая стабильная версия, которая новее, предлагается.

## Project Scope and Compatibility

- **Affected boundaries**: `streamdeck/` — проверка обновлений, отображение
  предложения в панели, версия из манифеста; упаковка в `streamdeck/scripts/`.
  `scripts/release.py` и `.github/workflows/release.yml` — версия плагина из
  тега, заметки о выпуске, состав ассетов. `Taskfile.yml` — при необходимости
  передача версии в упаковку. `README.md` и `README_RU.md` — установка из
  релиза и обновление. `cmd/sunset/`, `internal/` не меняются, кроме
  возможной согласованной передачи версии продукта контроллеру при сборке.
- **User-facing contract**: Новый ассет установщика в каждом релизе; версия
  плагина в Stream Deck равна версии тега; в панели любого действия MeRGBW
  появляется уведомление о новой версии с кнопкой установки и ссылкой на
  заметки. HTTP/CLI-контракт контроллера, действия, пресеты и настройки не
  меняются.
- **Compatibility**: Установка новой версии поверх старой сохраняет
  конфигурацию в Application Support, токен, пресеты, назначения клавиш, язык
  и пользовательские значки (поведение 007). Уже установленная 0.2.0.0 не
  умеет проверять обновления — первый переход на версию с проверкой выполняется
  вручную. Имя файла установщика может измениться; README и заметки
  обновляются вместе.
- **Verification boundary**: Сборку, версию, состав релиза, разбор заметок,
  сравнение версий и логику предложения можно проверить автоматически без
  Stream Deck, Bluetooth и сети (синтетические ответы о релизах). Установка
  скачанного установщика на Mac, срабатывание предложения в реальном Stream
  Deck и работа с LT-06 после обновления требуют ручного подтверждения
  владельцем. Успешная установка не доказывает физическое состояние лампы.
- **Constitution impact**: Плагин впервые обращается в интернет (только к
  публичным данным о релизах этого репозитория). Контракт loopback-HTTP
  контроллера не меняется. Тесты остаются без сети — принцип о тестах
  соблюдается. Поправка конституции не требуется, но исключение фиксируется в
  плане.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Тег выпускает готовый к установке плагин (Priority: P1)

Владелец пушит тег `vX.Y.Z`. Без ручных шагов появляется GitHub-релиз с
установщиком плагина, версия которого равна `X.Y.Z`. Владелец скачивает
установщик из релиза, открывает его, Stream Deck устанавливает плагин, и после
настройки лампы (или с сохранённой настройкой) клавиши управляют лампой.

**Why this priority**: Без корректного версионированного установщика ни
заметки, ни обновления не имеют смысла.

**Independent Test**: Выпустить тестовый тег-пререлиз, скачать установщик из
релиза браузером, установить на Mac владельца, проверить версию в Stream Deck
и одну команду лампе.

**Acceptance Scenarios**:

1. **Given** запушен тег `v1.3.0`, **When** релизный процесс завершается,
   **Then** релиз содержит установщик плагина, версия плагина внутри — `1.3.0`,
   а контрольная сумма есть в `SHA256SUMS`.
2. **Given** тег некорректен (не `vX.Y.Z` / `vX.Y.Z-pre`) или версия не
   переносится в манифест, **When** запускается релиз, **Then** публикация
   останавливается до создания релиза с понятной ошибкой.
3. **Given** установщик скачан из релиза браузером, **When** владелец открывает
   его на Mac, **Then** Stream Deck устанавливает плагин; после однократного
   шага из инструкции релиза (снятие карантина или разрешение в Privacy &
   Security) встроенный контроллер запускается (см. FR-004).
4. **Given** старая версия плагина уже настроена, **When** установлена новая,
   **Then** настройки, токен, пресеты и назначения клавиш сохранены, клавиши
   работают без повторной настройки.

---

### User Story 2 - Заметки о выпуске перечисляют все изменения (Priority: P2)

Открывая релиз, владелец видит все изменения с предыдущего релиза —
сгруппированные, со ссылками на коммиты — и понимает, что нового в плагине.

**Why this priority**: Нужны как для решения об обновлении, так и как текст,
который показывает предложение обновления.

**Independent Test**: Сгенерировать заметки локально для тега на истории с
коммитами разных типов и сравнить со списком коммитов между тегами.

**Acceptance Scenarios**:

1. **Given** между прошлым и новым тегом есть коммиты, **When** генерируются
   заметки, **Then** каждый коммит без merge присутствует ровно один раз в
   своей группе, с автором и ссылкой.
2. **Given** прошлый тег — пререлиз, **When** выпускается стабильный тег,
   **Then** заметки охватывают изменения с предыдущего стабильного релиза, чтобы
   пользователь стабильных версий видел всё, что пропустил.
3. **Given** релиз опубликован, **When** открываются заметки, **Then** в них
   указаны версия плагина, ссылка на установщик и порядок обновления
   (открыть установщик; настройки сохраняются).

---

### User Story 3 - Установленный плагин предлагает обновиться (Priority: P2)

Когда выходит новая стабильная версия, установленный плагин сообщает об этом
в панели действия: текущая и новая версия, краткие изменения, кнопки
«Установить» и «Позже». «Установить» скачивает установщик этого релиза,
проверяет его и передаёт Stream Deck, который показывает своё стандартное
подтверждение установки.

**Why this priority**: Прямой запрос владельца; зависит от US1 (версия из
тега).

**Independent Test**: С синтетическим источником данных о релизах (новее /
равен / старее / ошибка сети) проверить показ предложения, отказ, повтор и
передачу проверенного файла установщику без реальной сети и Stream Deck.

**Acceptance Scenarios**:

1. **Given** установлена `1.2.0`, а последний стабильный релиз — `1.3.0` с
   установщиком, **When** плагин выполняет проверку, **Then** появляется одно
   системное уведомление macOS о `1.3.0`, а в панели любого действия видно
   предложение с обеими версиями, ссылкой на заметки и кнопкой установки;
   клавиши продолжают работать как раньше.
2. **Given** предложение показано, **When** владелец нажимает «Установить»,
   **Then** установщик скачивается, его контрольная сумма сверяется с
   `SHA256SUMS` релиза, и при совпадении открывается стандартная установка
   Stream Deck; при несовпадении или ошибке загрузки установка не запускается,
   показывается причина и ссылка на страницу релиза.
3. **Given** владелец нажал «Позже», **When** выполняются следующие проверки,
   **Then** предложение для этой версии не всплывает повторно до перезапуска
   плагина, но остаётся доступно в разделе диагностики/настроек; более новая
   версия показывается снова.
4. **Given** установленная версия равна или новее последнего стабильного
   релиза, либо последний релиз — пререлиз, **When** выполняется проверка,
   **Then** предложение не показывается.
5. **Given** нет сети или сервис релизов недоступен/ограничил запросы, **When**
   выполняется проверка, **Then** управление лампой не затрагивается,
   пользователю не показывается ошибка на клавишах, следующая попытка будет по
   расписанию.
6. **Given** владелец выключил проверку обновлений в настройках плагина,
   **When** проходит время проверки, **Then** обращений к сервису релизов нет.

### Edge Cases

- Установлена локальная сборка `1.2.0.7`, последний релиз — `1.2.0`: предложения
  нет. Выходит `1.2.1`: предлагается, как обычное обновление.
- Релиз без ассета плагина или без `SHA256SUMS` (ручной или частичный) — не
  предлагать установку, только ссылку на страницу релиза.
- Черновик релиза — не виден и не предлагается.
- Версия тега с суффиксом пререлиза — релиз помечен как пререлиз, в
  стабильном канале не предлагается; сравнение версий корректно для
  `1.10.0 > 1.9.0` и `1.3.0 > 1.3.0-rc.1`. Если вручную установлен
  пререлиз `1.3.0-rc.1`, а вышел стабильный `1.3.0`, стабильный предлагается.
- Установка запущена во время выполнения действия на лампе — установка Stream
  Deck перезапускает плагин; действующие правила 007 отменяют незавершённые
  шаги без дополнительной команды Off.
- Ответ сервиса релизов искажён или слишком велик — проверка считается
  неудачной, без падения плагина.
- Заметки содержат разметку/ссылки — в панели отображаются как безопасный
  текст, без выполнения кода.
- Уведомления macOS запрещены или недоступны: предложение есть только в
  панели, ошибок нет, повторных попыток показать уведомление для этой версии
  нет.
- В диагностику не попадают токен, идентификатор лампы и пути импорта;
  записывается только результат проверки и версии.
- Повторный запуск релизного процесса для уже опубликованного релиза — релиз
  не изменяется (сохраняется текущее поведение).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Публикация тега `vX.Y.Z[-pre]` MUST без ручных шагов создавать
  релиз с установщиком плагина, архивами контроллера, `SHA256SUMS` и
  заметками (сохранение текущего поведения).
- **FR-002**: Версия плагина в установщике релиза MUST выводиться из тега
  (`vX.Y.Z` → `X.Y.Z.0`); исходная версия в репозитории вручную не меняется.
  Несоответствие MUST останавливать релиз до публикации.
- **FR-002a**: Локальная сборка MUST получать версию `X.Y.Z.N`. Здесь `X.Y.Z`
  берётся из ближайшего достижимого тега (без тега — из исходного манифеста),
  а `N ≥ 1` увеличивается на 1 с каждой локальной сборкой. При сравнении
  версий четвёртое число учитывается после `X.Y.Z`. Поэтому `1.2.0.7` новее
  релиза `1.2.0` и старше релиза `1.2.1`: последний плагину предлагается.
- **FR-003**: Имя ассета установщика MUST быть стабильным между релизами,
  чтобы плагин мог найти его в любом релизе без знания конкретной версии.
- **FR-004**: Установщик из релиза MUST устанавливаться и запускать встроенный
  контроллер на Mac владельца после скачивания браузером. Подпись остаётся
  ad-hoc, без Developer ID, нотаризации и секретов Apple в CI (решение
  владельца, 2026-10-25). Заметки о выпуске и оба README MUST описывать
  однократный шаг для скачанного установщика: снять карантин либо разрешить
  запуск в **System Settings → Privacy & Security**. Если macOS блокирует
  контроллер, панель MUST показывать эту причину и ссылку на инструкцию, а не
  общую ошибку запуска.
- **FR-005**: Заметки о выпуске MUST перечислять все коммиты без merge с
  предыдущего релиза того же канала (стабильный → с прошлого стабильного),
  сгруппированные по типу, с автором и ссылкой, плюс версию плагина, ссылку
  на установщик и инструкцию обновления.
- **FR-006**: Установленный плагин MUST проверять последний стабильный
  опубликованный релиз репозитория при запуске и затем не чаще раза в 24 часа,
  и показывать предложение только если релиз строго новее установленной
  версии и содержит установщик.
- **FR-007**: Предложение MUST показываться в панели любого действия MeRGBW
  с текущей и новой версией, кратким текстом изменений (безопасно
  отображённым) и ссылкой на полную страницу релиза; клавиши не получают
  ошибок и продолжают работать.
- **FR-007a**: При первом обнаружении каждой новой версии плагин MUST
  показать одно системное уведомление macOS («Доступна MeRGBW X.Y.Z», EN/RU).
  Для этой версии уведомление не повторяется, в том числе после перезапуска
  плагина и после «Позже». Если macOS запрещает уведомления или их нельзя
  показать, предложение остаётся в панели без ошибки. Уведомление не содержит
  секретов. Если автопроверка выключена, уведомлений нет.
- **FR-008**: «Установить» MUST скачивать установщик релиза, сверять его
  SHA-256 с `SHA256SUMS` того же релиза и только при совпадении передавать
  его Stream Deck для стандартного подтверждения установки. Скачивание и открытие
  установщика начинаются только по нажатию «Установить». Ни автоматического
  открытия окна установки, ни тихой установки нет.
- **FR-009**: Ошибки проверки и загрузки (сеть, лимиты, отсутствие ассета,
  несовпадение суммы, искажённый ответ) MUST не влиять на управление лампой
  и отображаться только в панели/диагностике.
- **FR-010**: Владелец MUST иметь возможность выключить автоматическую
  проверку обновлений и запустить проверку вручную из панели; по умолчанию
  проверка включена.
- **FR-011**: Плагин MUST обращаться в сеть только за публичными данными о
  релизах этого репозитория и их ассетами, не передавая настроек, токена,
  идентификатора лампы или иных данных пользователя.
- **FR-012**: Обновление MUST сохранять конфигурацию, пресеты, токен,
  назначения клавиш, язык и пользовательские значки (поведение 007).
- **FR-013**: README.md и README_RU.md MUST описывать установку из релиза,
  проверку обновлений, её отключение и ручной первый переход с 0.2.0.0.

### Interfaces and Device Effects

- **Релиз**: тот же набор ассетов; установщик плагина со стабильным именем и
  версией из тега; заметки дополнены разделом обновления плагина.
- **Панель Stream Deck**: блок «Доступно обновление» (EN/RU), кнопки
  «Установить», «Позже», ссылка на заметки; в настройках — переключатель
  автопроверки и «Проверить сейчас»; состояние последней проверки.
- **Системное уведомление macOS**: одно на каждую новую версию (EN/RU), без
  секретов; если уведомления запрещены, остаётся только панель.
- **Сеть**: исходящие запросы плагина только к публичным данным релизов
  репозитория. Контроллер `sunset`, HTTP-маршруты, CLI, протокол и BLE не
  меняются.
- **Логи плагина**: события проверки (версии, результат, категория ошибки),
  без секретов.
- **Физические эффекты**: нет новых. Перезапуск плагина при установке
  останавливает его контроллер по правилам 007.

### Verification Evidence

- **Автоматически (без сети, Stream Deck, Bluetooth)**: перенос версии тега в
  манифест и отказ при несоответствии; стабильное имя ассета; генерация
  заметок для стабильного тега после пререлиза; сравнение версий; решение о
  показе предложения для новее/равно/старее/пререлиз/без ассета; «Позже»;
  выключенная проверка; одно системное уведомление на версию, в том числе
  после перезапуска, и работа без него при запрете уведомлений; ошибка сети/искажённый ответ; несовпадение суммы
  блокирует установку; безопасное отображение заметок; отсутствие секретов в
  логах.
- **Вручную у владельца (pending до наблюдения)**: тестовый тег-пререлиз
  выпускает релиз; скачанный браузером установщик устанавливается и
  контроллер запускается; обновление с версии N на N+1 через предложение в
  панели сохраняет настройки; одна команда лампе после обновления.
  Ненаблюдённые варианты фиксируются как принятые пробелы, не как пройденные.

### Key Entities

- **Релиз**: тег, признак пререлиза/черновика, заметки, ассеты (установщик
  плагина, `SHA256SUMS`, архивы контроллера).
- **Версия плагина**: значение из тега, записанное в манифест; сравнивается
  по semver.
- **Состояние проверки обновлений**: включена ли проверка, время последней
  проверки, найденная версия, отложенная («Позже») версия, версия, о которой
  уже было системное уведомление, последняя ошибка.
- **Предложение обновления**: текущая и новая версия, краткие изменения,
  ссылка на релиз, ссылка на установщик и его ожидаемая сумма.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После пуша тега релиз с установщиком появляется без ручных
  действий в 100% успешных прогонов; версия плагина в Stream Deck совпадает с
  тегом.
- **SC-002**: Владелец устанавливает плагин из скачанного установщика и
  отправляет первую команду лампе за ≤ 5 минут без терминала (при
  сохранённой конфигурации — без повторной настройки).
- **SC-003**: Заметки содержат 100% коммитов без merge между релизами канала.
- **SC-004**: Новая стабильная версия предлагается установленному плагину не
  позже чем через 24 часа работы (или сразу при запуске плагина), а обновление
  от предложения до работающей новой версии занимает ≤ 3 действий владельца.
- **SC-005**: Ни одна ошибка проверки/загрузки обновления не приводит к
  отказу команды лампе; установщик с несовпадающей суммой не открывается ни
  разу.
- **SC-006**: Ручное подтверждение US1 и US3 на Mac владельца записано как
  наблюдение; ненаблюдённые сценарии — как принятые пробелы.

## Assumptions

- Канал обновлений — только стабильные релизы; пререлизы публикуются, но не
  предлагаются. Отдельный канал бета-версий — вне объёма.
- Репозиторий релизов публичный; доступ без учётных данных, лимиты анонимных
  запросов достаточны при проверке раз в 24 часа.
- «Предложить установить» = уведомление в панели + установка через
  стандартное подтверждение Stream Deck; автоматическая тихая установка и
  откат на прошлую версию вне объёма.
- Метка обновления на самих клавишах вне объёма, чтобы не смешивать её со
  статусом команд. Внимание привлекает системное уведомление macOS.
- Цель — Mac владельца (Apple Silicon, macOS 13.5+, Stream Deck 7.1+);
  Intel остаётся заявленной, но непроверенной целью, как в 007.
- Версия контроллера `sunset` в архивах может по-прежнему задаваться
  отдельно; связывание её с тегом — допустимое, но необязательное улучшение.
- Публикация в Elgato Marketplace вне объёма.
