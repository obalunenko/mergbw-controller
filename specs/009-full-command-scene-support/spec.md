**Feature Directory**: `specs/009-full-command-scene-support`

**Feature Branch**: `master` — существующая ветка; нумерация каталога не создаёт ветку.

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: «добавь поддержку всех команд и сцен из https://github.com/King1704G/custom_components-sunset_light_cheapass_amazon_light/blob/main/custom_components/sunset_light/control.py поддерживаются»

## Reference Inventory

Справочный `control.py` (интеграция Home Assistant, тот же формат кадра
`55 <cmd> FF <len> <payload> <checksum>`, запись в `FFF3`) содержит:

| Команда справочника | Код | Данные | Состояние в проекте |
|---|---|---|---|
| `turn_on` / `turn_off` | `0x01` | `01` / `00` | Уже есть: `on`, `off` |
| `set_color` | `0x03` | `R G B` | Уже есть: `color RRGGBB` |
| `set_white` | `0x03` | `FF FF FF` | Уже есть как `color FFFFFF` |
| `set_brightness` | `0x05` | один байт | Уже есть: `brightness 0–100` |
| `set_scene` | `0x06` | один байт ID сцены | **Отсутствует** — предмет этой фичи |
| `CMD_WHITE_OFF = 0x00` | — | — | В справочнике объявлена, но нигде не используется; не переносится |

Сцены справочника (ID — байт данных команды `0x06`):

| Название | ID | Пометка справочника |
|---|---|---|
| fantasy | `0x80` | не подтверждено |
| green prairie | `0x81` | подтверждено автором |
| sunset | `0x82` | не подтверждено |
| forest | `0x82` | не подтверждено; дублирует ID sunset |
| sunrise | `0x83` | не подтверждено |
| ghost | `0x84` | подтверждено автором |
| midsummer | `0x85` | не подтверждено |
| tropicaltwilight | `0x86` | не подтверждено |
| disco | `0x87` | подтверждено автором |
| alarm | `0x88` | подтверждено автором |
| rubyglow | `0x89` | не подтверждено |
| aurora | `0x89` | не подтверждено; дублирует ID rubyglow |
| savanah | `0x8B` | подтверждено автором |
| lake placid | `0x8C` | не подтверждено |
| neon | `0x8D` | не подтверждено |
| sundowner | `0x8E` | не подтверждено |
| bluestar | `0x8F` | не подтверждено |
| redrose | `0x90` | не подтверждено |
| rating | `0x91` | не подтверждено |
| autumn | `0x93` | не подтверждено |

Основным в паре дублей считается название, которое в справочнике идёт
раньше (sunset, rubyglow); это выбор проекта, а не утверждение справочника.
ID `0x8A` и `0x92` в справочнике не назначены. «Подтверждено автором» относится
к лампе автора справочника, а не к LT-06 владельца этого проекта.

## Project Scope and Compatibility

- **Affected boundaries**: `internal/protocol/` — каталог сцен, валидация и
  кодирование команды сцены; `internal/bridge/` — новый маршрут сцены в
  существующем GET/POST-контракте; `internal/config/` — строки сцен в
  `streamdeck-buttons.txt`; `cmd/sunset/` — справка CLI; `streamdeck/` — выбор
  сцены в плагине; `README.md` и `README_RU.md` — описание команд и статуса
  проверки. `internal/controller/` и `internal/ble/` переиспользуются без
  изменения контракта.
- **User-facing contract**: Новая CLI-команда `scene <name>`, новый
  маршрут `/<token>/scene/<name>` (GET и POST, HEAD не выполняет), новое
  действие Scene в плагине Stream Deck, строки сцен в списке ссылок. Прежние
  команды, маршруты, ответы и пресеты не меняются.
- **Compatibility**: Существующие настройки, токены, пресеты и назначенные кнопки
  продолжают работать без миграции. Повторный `init` сохраняет настройки и
  пересоздаёт `streamdeck-buttons.txt`: прежние строки не меняются, после них
  добавляются строки сцен.
- **Verification boundary**: Без устройства проверяются: валидация названий,
  точные байты кадра и контрольная сумма, маршрутизация, ответы и отмена
  динамических эффектов. Внешний вид и соответствие каждой сцены её названию на
  LT-06 владельца требуют локальной аппаратной проверки; отправленный пакет не
  считается подтверждением.
- **Constitution impact**: Принципы I–VI сохраняются. Сцена — абсолютная
  команда, её повтор после переподключения безопасен. Поправка конституции не
  требуется.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Запустить встроенную сцену лампы (Priority: P1)

Владелец выбирает одну из встроенных анимированных сцен LT-06 (например, Disco
или Aurora) из CLI или по ссылке Stream Deck. Лампа включается и запускает
сцену своими силами, без постоянной отправки пакетов с компьютера.

**Why this priority**: Это единственная команда справочника, которой пока нет в
проекте, и основная ценность запроса.

**Independent Test**: Выполнить `sunset send scene disco` и запрос
`GET /<token>/scene/disco`; убедиться, что отправлены кадр включения и кадр
`55 06 FF 06 87 <checksum>`, а ответ содержит `physical_state_verified: false`.

**Acceptance Scenarios**:

1. **Given** запущенный контроллер и известное название сцены, **When** владелец
   отправляет команду сцены, **Then** контроллер последовательно отправляет
   включение и кадр сцены с ID из каталога и сообщает об отправке без заявления
   о физическом состоянии.
2. **Given** неизвестное название сцены, **When** владелец отправляет команду,
   **Then** ничего не отправляется, CLI показывает список доступных сцен, HTTP
   возвращает 400.
3. **Given** работает программный эффект или переход, **When** владелец
   запускает сцену, **Then** эффект или переход останавливается до отправки
   кадра сцены и больше не перезаписывает свет.

---

### User Story 2 - Назначить сцену кнопке Stream Deck (Priority: P2)

Владелец добавляет на Stream Deck действие Scene, выбирает сцену из списка и
нажимает кнопку. Пользовательский список ссылок также содержит готовые адреса
сцен для Website-кнопок.

**Why this priority**: Stream Deck — основной способ управления; без действия
сцену пришлось бы вызывать вручную.

**Independent Test**: Добавить действие Scene, выбрать сцену, нажать кнопку и
увидеть подтверждение отправки; перезапустить плагин и убедиться, что выбор
сохранён.

**Acceptance Scenarios**:

1. **Given** плагин установлен, **When** владелец выбирает сцену в действии
   Scene и нажимает кнопку, **Then** выполняется та же команда, что и в US1, а
   кнопка показывает успех или ошибку как прочие действия. Заголовок кнопки —
   название сцены (например, «Disco»), для числового ID — «ID 8A».
2. **Given** выполнен `init`, **When** владелец открывает
   `streamdeck-buttons.txt`, **Then** в нём есть ссылка для каждой сцены
   каталога, а прежние ссылки не изменились.

---

### User Story 3 - Понимать, какие сцены проверены (Priority: P3)

Владелец видит в документации и списке сцен, какие сцены подтверждены на его
LT-06, какие только перенесены из справочника, а какие названия ведут на тот
же ID.

**Why this priority**: Половина справочного каталога не проверена и содержит
дубли; без пометок пользователь ошибочно примет пакет за проверенный эффект.

**Independent Test**: Открыть README и справку CLI; у каждой сцены есть
статус проверки, а для дублей указан общий ID.

**Acceptance Scenarios**:

1. **Given** каталог сцен, **When** владелец читает README (EN и RU), **Then**
   у каждой сцены указаны ID и статус: «проверено на LT-06» либо «не
   проверено».
2. **Given** владелец проверил сцену на своей лампе, **When** результат внесён
   в отчёт аппаратной проверки, **Then** её статус в документации обновляется
   без изменения команды.

### Edge Cases

- Название с пробелом (`green prairie`, `lake placid`): в CLI и URL
  принимается только идентификатор в нижнем регистре без пробелов (см. FR-002);
  вариант с пробелом или заглавными буквами, пустое название и лишние параметры
  отклоняются до отправки.
- Числовой ID сцены: `8A` и `92` принимаются; `7F`, `94`, `FF`, `8`, `8G`
  отклоняются (FR-003). Название, совпадающее с HEX-строкой, невозможно: все
  slug каталога содержат не-HEX буквы.
- HTTP: HEAD не выполняет команду; неверный Host или токен — 403/400 до
  разбора сцены; тело запроса отклоняется, как у прочих команд.
- BLE: обрыв соединения или таймаут во время отправки сцены обрабатываются
  существующими правилами повтора и кооперативной отмены; неопределённая запись
  не повторяется. Повтор после переподключения допустим, команда абсолютная.
- После сцены команда `color`, `brightness` или пресет перезаписывает режим
  лампы; контроллер не восстанавливает сцену и не отслеживает её как
  состояние.
- Повторный `init` с конфликтующей identity по-прежнему отклоняется; список
  ссылок обновляется только при успешной инициализации.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST поддерживать команду сцены в CLI (`scene <name>`),
  HTTP (`/<token>/scene/<name>`, GET и POST) и плагине Stream Deck, отправляя
  включение (`0x01 01`) и затем кадр `0x06` с однобайтовым ID сцены в
  существующем формате кадра и контрольной суммы.
- **FR-002**: Каталог MUST содержать по одной сцене на каждый ID `80`–`93`
  (20 записей). Идентификатор сцены — название в нижнем регистре без пробелов.
  Названия описывают эффект, наблюдавшийся на LT-06 владельца 2026-10-25
  (`red`, `rgbfade`, `redpulse`…): названия справочника с ним в основном не
  совпали и оставлены только в документации для сверки. *(Решение владельца
  после аппаратной проверки, 2026-10-25.)*
- **FR-003**: Помимо названий система MUST принимать сцену по числовому ID в
  виде двух HEX-цифр (`scene 8A`, `/<token>/scene/8A`, без учёта регистра,
  префикс `0x` допускается и в CLI, и в HTTP) в диапазоне `80–93`, включая неназначенные
  `8A` и `92`, чтобы владелец мог исследовать сцены на своей лампе. ID вне
  диапазона и не-HEX значения отклоняются без отправки. Маршрут в ответе и
  логах — `scene/<ID в верхнем регистре>`. Действие Scene в Stream Deck
  предлагает и названия, и ID. *(Решение владельца, 2026-10-25.)*
- **FR-004**: Сцена MUST валидироваться целиком до отправки любых пакетов;
  неизвестное или некорректное название не отправляет ничего и возвращает
  понятную ошибку со списком доступных сцен (CLI) или 400 (HTTP).
- **FR-005**: Запуск сцены MUST остановить активный программный эффект или
  переход до отправки кадра сцены, по тем же правилам, что и обычные команды.
- **FR-006**: Действие сцены MUST выполняться как одно сериализованное
  действие, с существующими правилами повтора, таймаута и кооперативной отмены.
- **FR-007**: Ответ и логи MUST сообщать маршрут `scene/<name>` и число пакетов,
  сохранять `physical_state_verified: false` и не раскрывать токен или полные
  URL.
- **FR-008**: `streamdeck-buttons.txt` MUST содержать ссылку для каждой сцены
  каталога; существующие строки и токены сохраняются.
- **FR-009**: Плагин Stream Deck MUST предоставлять действие Scene с выбором
  сцены из каталога и сохранением выбора, заголовком кнопки по названию сцены и
  учётом действия в диагностике плагина; прежние шесть действий и их настройки
  не меняются.
- **FR-010**: README.md и README_RU.md MUST согласованно описывать команду
  сцены, полный список сцен с ID и статусом проверки, а также то, что белый
  свет задаётся существующей командой `color FFFFFF`.
- **FR-011**: Сцены MUST NOT входить в пользовательские пресеты в этой фиче:
  формат `presets.json` не меняется.
- **FR-012**: Влияние яркости на сцену не гарантируется: команда `brightness`
  после сцены отправляется как обычно, но её эффект на анимацию считается
  непроверенным до аппаратной проверки.

### Interfaces and Device Effects

- **CLI**: `sunset send scene <name>`; `sunset dry-run scene <name>` показывает
  два кадра без подключения к лампе. Справка перечисляет сцены.
- **HTTP**: `GET|POST /<token>/scene/<name>` → 200
  `{"sent": true, "action": "scene/<name>", "physical_state_verified": false}`;
  ошибки 400/403/404/503/504 по существующей схеме; лишний сегмент пути
  (`/<token>/scene/disco/extra`) — 404.
- **Пакеты**: `55 01 FF 06 01 <cs>`, затем `55 06 FF 06 <id> <cs>`. Пример:
  disco → `55 06 FF 06 87 <cs>`, где `<cs>` вычисляется существующим
  алгоритмом.
- **Stream Deck**: новое действие Scene со списком сцен в инспекторе; заголовок
  кнопки — название сцены или «ID 8A».
- **Конфигурация**: формат settings и presets не меняется; дополняется только
  генерируемый список ссылок.
- **Физический эффект**: лампа сама проигрывает сцену; продолжительность,
  цвета и реакция на яркость не контролируются и не считываются контроллером.

### Verification Evidence

- **Автоматически**: тесты протокола на точные байты всех 20 записей и их
  контрольные суммы; отклонение неизвестных/некорректных названий; HTTP-тесты
  GET/POST/HEAD, токена и тела; остановка эффекта перед сценой; генерация
  ссылок; тесты действия Scene в плагине. Все — без нативного Bluetooth.
- **Вручную на LT-06** (pending): для каждой сцены отметить, наблюдался ли
  эффект и соответствует ли он названию; отдельно проверить дубли и реакцию на
  `brightness`. Результаты записываются в отчёт аппаратной проверки этой фичи.

### Key Entities

- **Scene**: идентификатор (стабильный slug), отображаемое название по
  наблюдаемому эффекту и уникальный ID байта команды `0x06`.
- **Scene catalog**: фиксированный, поставляемый с контроллером список сцен;
  не редактируется пользователем.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все 20 сцен справочника можно запустить из CLI, HTTP и Stream Deck
  одним действием; доля сцен с точно совпадающими со справочником байтами — 100%.
- **SC-002**: 100% некорректных запросов сцены отклоняются без отправки
  пакетов; существующие команды и ссылки работают без изменений (все прежние
  автоматические проверки проходят).
- **SC-003**: После запуска сцены программный эффект больше не отправляет
  пакеты (0 пакетов эффекта после пакета сцены в автоматическом сценарии).
- **SC-004**: Для каждой сцены в документации указан статус проверки; ни одна
  сцена не помечена «проверено» без записи в отчёте аппаратной проверки.

## Assumptions

- LT-06 владельца принимает команду `0x06` так же, как лампа автора
  справочника; это пока не подтверждено.
- Включение перед сценой повторяет схему команд `color` и `brightness`.
- Отдельная команда `white` не добавляется: справочный `set_white` равен
  `color FFFFFF`, который уже проверен на LT-06.
- `CMD_WHITE_OFF` из справочника не используется в его коде и не переносится.
- Чтение состояния лампы, редактор сцен, сцены в пресетах, скорость сцены и
  интеграция с Home Assistant вне объёма.
- Каталог сцен поставляется в коде и не настраивается пользователем.
