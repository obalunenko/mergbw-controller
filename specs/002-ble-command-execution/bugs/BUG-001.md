# Bug Report: Native BLE Lifecycle Lacks Controlled Regression Coverage

**Type**: Untested flow
**Severity**: High
**Feature**: 002-ble-command-execution — BLE Connection and Command Execution
**Reported**: 2026-10-20
**Status**: Patched
**Patched**: 2026-10-20
**Implementation**: Completed (automated coverage)
**Implemented**: 2026-10-21
**Source gap**: G01

## Description

The native backend implements connection reuse, scanning, GATT discovery,
synchronous writes, and disconnect cleanup, but the existing BLE tests do not
exercise their successful lifecycle or the failure/race paths listed below.
Regressions in link readiness, cancellation ownership, uncertain writes, and
cleanup can therefore escape the current suite. This report records missing
verification; no runtime failure has been reproduced.

## Evidence and Reproduction

The evidence below records the original reporting snapshot; the current
baseline and remaining scope are annotated in the Patch Record.

Inspect [backend_test.go](../../../internal/ble/backend_test.go): its five Test
functions cover advertisement matching, missing identity, early cancellation,
an injected sticky failure, and a synthetic disconnect callback. They do not
drive native scan/connect/discovery/write/disconnect results.

The corresponding behavior is in
[backend.go](../../../internal/ble/backend.go), particularly connectLocked,
scanLocked, discoveryErrorLocked, Write, infoLocked, and closeLocked. Concrete
Bluetooth handles currently make those operations difficult to control in tests.

On this macOS host, the BLE test binary was compiled during the preceding audit
but was not executed. Compilation does not demonstrate these paths.

## Root Cause Analysis

The reconstructed feature has pure matcher and early-exit tests, but lacks a
controlled way to supply successful and failing native operation results. Its
historical test evidence consequently stops before the lifecycle most affected
by platform callbacks and resource ownership. No dependency malfunction or
implementation drift is established by this gap alone.

## Recommended Fix

1. Run `$speckit-bugfix-patch` for BUG-001 to encode the missing coverage in the
   feature artifacts and add traceable tasks.
2. Cover successful connection/reuse; missing or duplicate FFF0/FFF3; empty or
   wrong-device connect results; cancellation between native stages; first-match
   selection; StopScan races and stopper joining; scan-only expiry versus parent
   cancellation and native errors.
3. Cover synchronous write completion, packet copying/readiness checks,
   post-write cancellation, error-free short writes and errors.Is uncertainty
   classification. Preserve the specified native-error precedence.
4. Cover close/drain, already-disconnected handling, failed-disconnect handle
   retention and later cleanup, sticky Darwin discovery timeout installation
   and persistence across Close, and Inspect metadata copying without writes,
   reads, subscriptions, or verification claims.
5. Run `$speckit-bugfix-verify`, then `$speckit-implement`. Use controlled tests
   that do not require native Bluetooth initialization in macOS core checks;
   keep any actual device observations separate under H01.
