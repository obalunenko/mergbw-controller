# Bug Report: Backend Input Boundaries and Error Precedence Lack Tests

**Type**: Untested flow
**Severity**: Medium
**Feature**: 002-ble-command-execution — BLE Connection and Command Execution
**Reported**: 2026-10-20
**Status**: Patched
**Patched**: 2026-10-20
**Implementation**: Completed (automated coverage)
**Implemented**: 2026-10-21
**Source gap**: G02

## Description

Backend construction and Write implement explicit identity, timeout, and packet
size validation, but focused tests do not enumerate their boundaries or the
order of early errors. Invalid input could start being accepted, valid boundary
values rejected, or canceled/failed operations classified differently without
being detected by the current suite. This is a coverage defect; current runtime
validation has not been shown to violate the specification.

## Evidence and Reproduction

The evidence below records the original reporting snapshot; the current
baseline and remaining scope are annotated in the Patch Record.

Inspect [backend_test.go](../../../internal/ble/backend_test.go):
TestNewRequiresExplicitIdentity checks only an empty identity;
TestCancelledOperationsLogWithoutStartingBLE uses a valid one-byte packet;
TestStickyConnectionFailureLogsErrorWithRequestContext checks Connect rather
than Write. No table covers malformed identity, timeout boundaries/defaults,
invalid packet lengths, or combinations of early-error conditions.

The relevant implementation is New, parseIdentity, and Write in
[backend.go](../../../internal/ble/backend.go). Write checks length first,
then context, fatal state, and link handles after acquiring its mutex.

## Root Cause Analysis

Existing tests exercise representative early failures rather than the complete
input contract. The migration documented the behavior and retained this known
gap, without adding the boundary fixtures needed to protect it.

## Recommended Fix

1. Run `$speckit-bugfix-patch` for BUG-002 and add traceable acceptance cases
   and test tasks.
2. Cover malformed identity segment counts/lengths and non-HEX characters,
   lowercase-to-uppercase normalization, both 12s defaults, scan values below
   and at 1ms, and connect values below/at 1ms and at/above 40s. Preserve the
   special zero-default behavior and the absence of a scan upper limit.
3. Cover 0/21-byte rejection and 1/20-byte acceptance by the length gate,
   without native writes. Assert errors.Is results for invalid length combined
   with canceled context and fatal state; valid length with cancellation and
   fatal state; and valid uncanceled input with missing link handles.
4. Run `$speckit-bugfix-verify`, then `$speckit-implement`. Use a non-native test
   boundary where needed so macOS core validation does not initialize BLE.
