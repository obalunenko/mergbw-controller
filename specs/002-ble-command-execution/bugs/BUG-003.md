**Status**: Patched
**Patched**: 2026-10-20

**Implemented**: 2026-10-21
**Source gap**: G03

## Description

Current fake-Link tests verify write-failure replay and cancellation, but do
not protect production typed-error classification, retryable Connect failures,
cleanup failures before replay, the default 80ms packet gap, or terminal Close
under contention. Regressions could replay an uncertain write, lose a cleanup
error, violate pacing, or accept work after Close without failing these tests.
These are potential consequences of missing coverage, not reproduced faults.

## Evidence and Reproduction

The evidence below records the original reporting snapshot; the current
baseline and remaining scope are annotated in the Patch Record.

Inspect [controller_test.go](../../../internal/controller/controller_test.go):

- fakeLink.CanRetry returns a boolean, bypassing the production classifier.
- fakeLink.Close always returns nil, so retry cleanup failure is untestable.
- TestRetryOnceAndRespectNonRetryableErrors injects write failures, not a
  retryable Connect failure. TestLogsFailuresBeforeAnyPacket covers a Connect
  error only with retries disabled.
- The sequence/retry/cancellation tests set c.gap = 0, leaving the default
  completion-relative packet spacing unasserted.
- The closed-command case calls Close on an idle controller. There is no
  blocked-operation/expired-Close-wait test or direct post-Close Connect test.

Production retry classification is lampLink.CanRetry in
[main.go](../../../cmd/sunset/main.go); there are no cmd/sunset test files.
Pacing, retry cleanup, and terminal close are implemented in
[controller.go](../../../internal/controller/controller.go).

## Root Cause Analysis

The current test doubles replace production retry policy with a boolean and
cannot simulate Close errors. Tests also disable pacing for speed and exercise
Close primarily after work has completed. These simplifications omit the
boundaries identified by G03 without proving an implementation defect.

## Recommended Fix

1. Run `$speckit-bugfix-patch` for BUG-003 to add explicit acceptance coverage
   and missing tasks to the feature artifacts.
2. Test actual lampLink.CanRetry for direct, wrapped, and joined cancellation,
   deadline, ErrIncompatible, ErrPermission, ErrNeedsRestart, ErrWriteUncertain,
   and ErrInvalidPacket errors; include retryable ordinary errors. Ensure the
   test arrangement avoids CoreBluetooth initialization in macOS core checks.
3. Test transient/persistent Connect failures and at most two attempts; inject
   Close failure and assert both causes survive errors.Is with no reconnect or
   replay after failed cleanup. Retain the 200ms retry-wait contract.
4. Assert the 80ms minimum spacing from completion of the previous successful
   or failed write, including across actions, using a controllable clock or
   bounded timing checks that do not introduce a new latency SLO.
5. Block a native-like operation, call Close with a live or expiring context,
   and assert exclusive cleanup, immediate terminal state, later Connect/Execute
   rejection, no abandoned writer, and eventual cleanup via a later Close when
   the first wait expired.
6. Run `$speckit-bugfix-verify`, then `$speckit-implement`; validate changes with
   macOS-safe core/race checks and appropriate vet/build checks.
